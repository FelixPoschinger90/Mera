# MERA E3.10-C — Character Proof

This is deliberately **not** the MERA game. It isolates the character replacement so a visual failure cannot destabilize the working E3.9.x study build.

## What is unchanged
- Ecctrl controller
- Rapier physics capsule
- direct keyboard input
- follow camera
- grounding / slope / step behaviour
- Three.js Soldier skeleton and its proven Idle / Walk / Run clips

## What changes
The Soldier armour meshes are hidden. A new civilian expedition-worker visual is mounted on the same animated bones at runtime: olive field jacket, dark trousers, hiking boots, backpack, exposed head/hair, empty hands.

The visible body has no authority over collision or movement. The Ecctrl capsule remains the player.

## Controls
- WASD / arrows: move
- Shift: run
- Space: jump
- drag mouse: orbit camera
- V: compare the original Soldier visual with the proposed field-worker visual

## Acceptance gate
Do not integrate into MERA unless the field-worker visual is upright, grounded, visually acceptable, and preserves idle/walk/run/slope/camera behaviour.

## Asset provenance
The hidden motion skeleton / animation source is Three.js `Soldier.glb`, used by the existing MERA prototype. This proof does not add a new downloaded character asset. The civilian shell geometry and materials are generated by this project at runtime and attached to the existing skeleton.

This is intentionally the lowest-risk character-replacement path. If the visual does not pass, the working MERA build remains untouched.
